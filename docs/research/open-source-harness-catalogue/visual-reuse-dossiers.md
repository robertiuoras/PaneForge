# Visual reuse dossiers

Checked 2026-09-13. These are design and implementation observations, not an instruction to add a dependency. A calm workbench needs clear state before visual flourish. Copying source remains subject to the licence named below; URLs point to the inspected source at the repository default branch, so pin a commit before any implementation review.

## 1. Controlled motion: Motion

- **Repository and licence:** [motiondivision/motion](https://github.com/motiondivision/motion), MIT.
- **What was inspected:** `packages/framer-motion/src/components/MotionConfig/index.tsx`, the React reduced-motion example at [`dev/react/src/examples/useReducedMotion.tsx`](https://github.com/motiondivision/motion/blob/main/dev/react/src/examples/useReducedMotion.tsx), layout-interruption fixtures under [`dev/html/public/animate-layout/`](https://github.com/motiondivision/motion/tree/main/dev/html/public/animate-layout), and animation/unit tests under [`packages/framer-motion/src/animation/__tests__/`](https://github.com/motiondivision/motion/tree/main/packages/framer-motion/src/animation/__tests__).
- **Observed pattern:** a component reads the user reduced-motion preference and replaces a timed transition with `type: false`. The repo also deliberately tests interruption, re-entry, cancellation, shared elements and parallel layout changes, rather than assuming an animation runs to completion.
- **Reuse as a PaneForge pattern:** task cards can fade or translate a very short distance when their factual status changes; an expanded task can use layout motion only after the underlying receipt is already rendered. An approval card should arrive immediately and then receive a restrained emphasis, never a looping pulse.
- **Precise edge cases to retain:** a user can Stop while an activity card is entering; a queued steer can turn a card from waiting to working before the first animation finishes; connection recovery can replace same-count list data. Render the final state without waiting for an exit animation. No animation may delay keyboard focus, screen-reader announcement, Stop, or approval controls.
- **Accessibility/performance:** respect `prefers-reduced-motion` globally; fall back to opacity or no animation, not a slower decorative substitute. Animate opacity and transform, avoid layout thrashing on terminal rows, and do not run perpetual effects for active sessions.
- **Attribution:** MIT permits reuse with its notice. Prefer reproducing the product behaviour with PaneForge-owned code after a specific decision, rather than importing the library solely for a few transitions.

## 2. Agent workspace state: Magentic-UI

- **Repository and licence:** [microsoft/magentic-ui](https://github.com/microsoft/magentic-ui), MIT.
- **What was inspected:** [`frontend/src/components/chat/ChatView.tsx`](https://github.com/microsoft/magentic-ui/blob/main/frontend/src/components/chat/ChatView.tsx), [`ChatInput.tsx`](https://github.com/microsoft/magentic-ui/blob/main/frontend/src/components/chat/ChatInput.tsx), [`SessionCard.tsx`](https://github.com/microsoft/magentic-ui/blob/main/frontend/src/components/session/SessionCard.tsx), [`messageList.test.tsx`](https://github.com/microsoft/magentic-ui/blob/main/frontend/src/test/messageList.test.tsx), [`verificationAlert.test.tsx`](https://github.com/microsoft/magentic-ui/blob/main/frontend/src/test/verificationAlert.test.tsx), plus its test tree.
- **Observed pattern:** the input changes its explicit available action from **Stop** to **Continue** using session state; browser takeover suppresses those controls until user feedback is supplied. Session cards obtain a status icon/configuration from one status mapping. Chat state preserves scroll per session and can jump to an important background completion, error or input request.
- **Reuse as a PaneForge pattern:** show one unmistakable primary next action, derived from durable task state: **Steer**, **Stop**, **Continue**, **Sign in**, **Approve**, or **Review proof**. When computer use is paused for Robert, the task’s receipt rail should say why and what releases it. Status colour is supplementary to text and icon.
- **Precise edge cases to retain:** do not derive list rendering solely from `messages.length`: the inspected regression test covers a same-length replacement that otherwise leaves stale memoized content. Keep optimistic IDs in a separated range or use a separate client identity; an acknowledgement must replace the draft event without duplicating or reordering the receipt. If a session exits during a browser/tool call, clear orphaned “in control” UI so the task can accept input again.
- **Accessibility/performance:** keep `aria-label`s and disabled semantics on action buttons. Important background events must be discoverable without auto-scrolling someone away from a review. This has stronger value for PaneForge than a moving agent graph.
- **Attribution:** MIT permits reuse with its notice. This is an architecture reference, not a recommendation to graft its React/Python product into PaneForge.

## 3. Assistant presence / voice visualizer: React Bits Orb

- **Repository and licence:** [DavidHDev/react-bits](https://github.com/DavidHDev/react-bits), **MIT + Commons Clause**. Its own [`LICENSE.md`](https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md) restricts commercial use; therefore this dossier is **pattern-only**. Do not copy code, shaders, media or assets into PaneForge/public releases without separate licence clearance.
- **What was inspected:** [`src/content/Backgrounds/Orb/Orb.jsx`](https://github.com/DavidHDev/react-bits/blob/main/src/content/Backgrounds/Orb/Orb.jsx), asset previews such as [`public/assets/video/orb.webm`](https://raw.githubusercontent.com/DavidHDev/react-bits/main/public/assets/video/orb.webm), and the project’s prop-documentation test script.
- **Observed pattern:** a full-canvas WebGL shader is driven by `requestAnimationFrame`; it normalises pointer position within an 0.8 radius, eases hover via a fixed `0.1` interpolation, and rotates at `0.3` units/second while hovered. It handles resize and explicitly loses the WebGL context on unmount.
- **Reuse as a PaneForge pattern:** if Astra gets a visual voice presence, use a small, static-by-default status mark. It can softly expand once on speaking/listening state changes and show an explicit label such as “Listening” or “Working”. The product must remain fully understandable with the mark hidden.
- **Why not copy the effect:** it requests a continuous frame loop, processes pointer motion and uses WebGL for a decorative object. That competes with terminal rendering and consumes battery/GPU even when it provides no task information. A voice visualizer should be audio-driven only while a live voice session is genuinely active, paused when occluded, disabled for reduced motion, and have a CSS/text fallback.
- **Test requirements for any owned replacement:** state transition snapshot tests for idle/listening/speaking/disconnected; test no animation frames run when hidden or reduced-motion is selected; test screen-reader text changes; instrument CPU/GPU impact during terminal output. This repository does not provide that validation for the particular Orb component.

## Recommendation

Use controlled two-dimensional motion for state continuity, retain an accessible factual receipt rail as the visual centre, and defer a voice-presence visual until live voice has a working permission, interruption and cost model. A graph is an on-demand inspection view, not the default way to understand agent work.
